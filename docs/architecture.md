# 工程结构

```text
.
├── Code/qgai/                 # 可安装的 Python 包
│   ├── classify/              # 业务分类适配器
│   ├── datamining/            # 表单、流程数据与本地 LLM 适配器
│   ├── face/                  # 人脸识别能力（按需加载）
│   ├── inquiry/               # 问答抽取能力（按需加载）
│   ├── lang/                  # 字段翻译资源
│   ├── server/                # HTTP / WebSocket 传输层
│   ├── voice/                 # 语音能力（按需加载）
│   ├── config.py              # 环境变量配置入口
│   ├── main.py                # 进程入口
│   └── user.py                # 用户会话与异步任务
├── docs/                      # 面向维护者的工程文档
└── pyproject.toml             # 唯一依赖与打包来源
```

## 边界约定

- 导入 `qgai` 不应加载模型、下载权重、创建目录或发起网络请求。
- 所有包内 JSON 与语言文件都相对模块路径读取，不依赖启动目录。
- 密钥、模型、训练产物、音视频样例和构建产物不进入 Git；部署时通过环境变量或制品仓库提供。
- 训练语料、真实表单、用户样例、成员照片、答辩材料和任务书可能包含个人信息，不进入公开仓库。
- HTTP 负责会话创建、分类、存储和汇总；WebSocket 负责交互问答、人脸和语音流。

## 后续拆分建议

当前第一轮保持了原接口。下一轮可把 `user.py` 进一步拆为 `domain/forms.py`、`domain/session.py` 与 `runtime/async_tasks.py`，并为模型适配器定义协议，随后再引入依赖注入和端到端接口测试。
